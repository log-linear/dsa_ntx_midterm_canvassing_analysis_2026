## Intent

**Problem:** The precinct research in `data/precinct_data.csv` is only inspectable as a flat 85-row, 89-column CSV. Organisers cannot see where canvass-based "no" share, response rate, and 2024 vote shares are geographically concentrated, or read a precinct's demographics alongside those numbers.

**Approach:** A single Streamlit app that draws the county's 2026 election precincts as a pydeck choropleth, joins the CSV onto each polygon, and turns a clicked precinct into a demographic detail panel. Labels come from `data_dictionary.csv`.

## Boundaries & Constraints

**Always:**
- Use the live ArcGIS FeatureServer REST endpoint for layer `2026 Election Precincts (Current)`; request `f=geojson` so geometry arrives as WGS84 lon/lat (the layer's native `wkid 103159` is Texas South in feet — never reproject client-side).
- Join on `NewPrcnt` ↔ `dallas_county_precinct_number`.
- Choropleth field is user-selectable across exactly these three, default `prop_a_city_no_canvassing_pct`: `canvass_attempts`, `response_rate`. *(Renegotiated by the human 2026-11-14, who split colourability out of the tooltip list; `2024_prop_r_for`, `2024_prop_u_against` and `2024_kamala` are now hover-only.)*
- Every precinct tooltip shows **all six** `TOOLTIP_FIELDS` with values, whichever one is selected for color.
- Clicking a polygon populates a second view with exactly these 26 fields: `median_age`, `median_household_income`, `not_us_citizen`, `pct_age_18_64`, `pct_age_20_39`, `pct_bachelors_plus`, `pct_below_poverty`, `pct_english_only`, `pct_family_households`, `pct_female`, `pct_hispanic`, `pct_households_snap`, `pct_hs_or_less`, `pct_income_under_50k`, `pct_married_couple_households`, `pct_multi_unit`, `pct_nh_asian`, `pct_nh_black`, `pct_nh_other`, `pct_nh_white`, `pct_owner_occupied`, `pct_single_unit`, `pct_spanish`, `pct_us_born`, `pct_vacant`, `population_per_sq_mi` — narrowed by Decision 1c below to the 17 that carry data.
- Display `readable_name` from `data_dictionary.csv` for every metric, never the raw field name.
- Disable built-in Streamlit telemetry in a committed config file.
- Distinguish blank from zero: `""` is no data; `0.0000` is a real value.

**Decisions from the human (2026-11-11):**
- **Fan-out is resolved at the source.** `precinct_data.csv` was deduplicated to one row per precinct (85 rows, 85 unique keys), so no row-picking rule is needed.
- **Fix labels at the root, in the generator.** `readable_name` values must be corrected in `build_data_dictionary.py` and the dictionary regenerated — not patched in the display layer and not hand-edited into the CSV (it is generated, so edits are clobbered). Rule: title-case, and expand the source's machine-mangled abbreviations — `pct`→`Percent`, `nh`→`Non-Hispanic`, `us`→`U.S.`, `snap`→`SNAP`, `50k`→`$50k`, `sq_mi`→`Square Mile`, `bachelors_plus`→`Bachelor's or Higher`. Examples: `'Pct age 18 64'`→`'Percent Age 18–64'`, `'Not us citizen'`→`'Not U.S. Citizen'`, `'Pct households snap'`→`'Percent Households on SNAP'`.
- **Basemap: free MapLibre, no key.** Use `map_provider="maplibre"` with a public CARTO style URL.
- **pandas is allowed** where it makes the code more parsimonious.
- **1c — the detail panel omits no-data fields.** The 9 fields blank in every row
  (`median_age`, `median_household_income`, `not_us_citizen`, `pct_below_poverty`,
  `pct_english_only`, `pct_households_snap`, `pct_spanish`, `pct_us_born`,
  `population_per_sq_mi`) are omitted from the detail view entirely, not rendered as `—`.
  Omitting them supersedes the 26-field list above: the panel shows the 17 populated fields.
- **2b — the label fix covers the whole dictionary.** Correct every mangled `readable_name`
  in `build_data_dictionary.py`, not just the fields this dashboard displays; the dictionary is
  shared metadata and half-fixed labels would leak into future tools.

**Never:**
- Do not modify `data/precinct_data.csv` or anything under `data/raw/` (upstream sources). `build_data_dictionary.py` and `data_dictionary.csv` may change only for the label fix above; no other edits.
- No new HTTP or geometry dependency: stdlib `urllib.request` + `csv` for I/O, plus `pandas`, `streamlit`, `pydeck`.
- No scraping the ArcGIS Instant Apps HTML; no database, no JS framework, no `st.map`/Altair for the map.
- Do not aggregate or average numeric values across rows.

## Code Map

- `data/precinct_data.csv` — 85 rows (deduplicated: `dallas_county_precinct_number` is unique), 89 cols. All 3 choropleth + 6 tooltip + 26 detail fields present as **strings**; blank is `""`. Fields starting with a digit (`2024_kamala`) are dict/DataFrame keys, never identifiers.
- `data/data_dictionary.csv` — cols `field_name,data_type,description,readable_name`; 89 entries, covers every field needed. **Generated file**: committed content == output of `build_data_dictionary.py` for all 89 fields, so regenerating is a no-op until the labels are intentionally changed.
- `build_data_dictionary.py` — the label source. 58 fields take `label` from `data/raw/dfs-export-precinct-20261108/dictionary.csv` (these are the ugly ones: `'Pct nh white'`); 31 are hand-authored in its `MANUAL` table with good labels. Its `readable_from_name()` fallback already title-cases. Apply the fix as a label override consumed after label selection, so the read-only DFS export is untouched. The 5 choropleth labels are already correct.
- GIS layer (verified live) — `https://services3.arcgis.com/zqe2kwz79KUqUvxC/arcgis/rest/services/2025_Proposed_Election_Precincts_791/FeatureServer/0/query?where=1=1&outFields=*&returnGeometry=true&f=geojson` → 4.6 MB, 791 `Polygon` features, one ring each, `NewPrcnt` unique and non-blank on all 791, `maxRecordCount` 2000 so **one request needs no pagination**; warm fetch ~0.15 s. 84/85 CSV precincts match.
- Per-field populated coverage on the 791 polygons — `prop_a_city_no_canvassing_pct` 24, `2024_prop_r_for` 63, `2024_prop_u_against` 63, `2024_kamala` 84, `response_rate` 25.
- Blank detail fields: `median_age`, `median_household_income`, `not_us_citizen`, `pct_below_poverty`, `pct_english_only`, `pct_households_snap`, `pct_spanish`, `pct_us_born`, `population_per_sq_mi` have **no value in any row**, and are likewise empty (0/796) in the DFS source export — this app cannot populate them. The other 17 are populated in all 85 rows.
- API facts (verified by running streamlit 1.67.0 / pydeck 0.9.3):
  - `pdk.Layer("PolygonLayer", data=<list of records>, id="<layer_id>", get_polygon="__rings", get_fill_color="__color", pickable=True, auto_highlight=True, stroked=False)` → serializes to `getPolygon`/`getFillColor`/`@@type: PolygonLayer`. **No `tooltip` here** — see the next bullet.
  - **CORRECTED 2026-11-12 — the `@@=` prefix does NOT mark a JS string.** pydeck prefixes *every* string layer prop with `@@=` (`bindings/layer.py:99-101`), and `@deck.gl/json` then **parses** it with a restricted expression grammar: quoted literals, record-key lookups, `+`, ternary, arithmetic, array literals. It does **not** evaluate JavaScript. `d => d.properties.__color` throws `Unexpected "=" at character 2` in the browser and `{token}` templates throw `Unexpected "{"` — both at render time, **invisible to every Python-side check, including `Deck.to_json()`**. Reproduce with `new JSONConverter().convert({'@@type':'PolygonLayer', getFillColor:'@@=' + expr})`.
  - **CORRECTED: a FeatureCollection dict is NOT usable as `data`.** Pass a **list of records** — polygon rings under `__rings`, per-feature attributes promoted to top-level keys on each record. Accessors then name record keys (`__color`), never `d.properties.x`.
  - Per-feature colors are a plain key on each record; a fixed `[r,g,b]` colors every polygon identically.
  - **CORRECTED 2026-11-12 — the tooltip is not a layer prop at all.** `st.pydeck_chart` accepts no `tooltip` argument; it lifts `pdk.Deck(tooltip=<dict>)` into its *own* protobuf field (`_get_pydeck_tooltip` → `pydeck_proto.tooltip`) and hands deck.gl a `getTooltip` of its own, which **overrides** the layer-level `tooltip` deck.gl would otherwise use. A `tooltip=` on the `Layer` therefore serialises into the spec, is never read, and the map looks flawless while hover shows nothing. Use `tooltip={"text": ...}` on the **Deck** (`text`, not `html`, because the frontend assigns `text` via `innerText`, so values from the live layer cannot inject markup).
  - Tooltip text on that channel uses a `{token}` template, and the frontend substitutes each token from the picked record: `"Precinct {NewPrcnt}\nProp R (For): {v_2024_prop_r_for}"`. Note this is the **opposite** grammar from the `@@=` layer props above — `{}` is a crash there and the only valid form here. `\n` breaks a line in `innerText`.
  - `st.pydeck_chart(deck, on_select="rerun", selection_mode="single-object", key=..., width="stretch", height=...)` returns `PydeckState`; clicked attributes are at `.selection.objects["<layer_id>"]` — a list of the feature's GeoJSON `properties` dicts. **`Layer(id=...)` is required** or selection state is unkeyed. `use_container_width` is superseded by `width="stretch"`.
  - Basemap: `map_provider="maplibre"` + a style **URL string** serializes cleanly (`mapStyle` = URL). A `dict` style raises `AssertionError: The map_provider parameter must be 'mapbox' when map_style is provided as a dict.` CARTO Positron `https://basemaps.cartocdn.com/gl/positron-gl-style/style.json` returns HTTP 200 keyless.
  - Telemetry: `browser.gatherUsageStats` (default `True`); env `STREAMLIT_BROWSER_GATHER_USAGE_STATS`; settable in `.streamlit/config.toml`.
  - `st.html(body)` sanitizes with DOMPurify but **keeps inline `style` attributes**, so a CSS-gradient legend survives it. Not iframed; JavaScript is dropped unless `unsafe_allow_javascript=True`. AppTest exposes it as `at.html[0].value` (the raw string), which makes the transport assertable instead of eyeball-only.
  - DOM handles for scripted checks in streamlit 1.67: `st.title` renders `h1[data-testid='stHeadingWithActionElements']` -- there is **no** `[data-testid='stTitle']`. The selectbox opens via `[data-testid='stSelectbox'] input[role='combobox']`; its options carry `role='option'` but are **not `li` elements** (baseui virtualises them), so `querySelectorAll('li[role=option]')` returns nothing. Drive it with `ArrowDown`/`Enter` or query `[role='option']` directly.
- `dashboard.py`, `.streamlit/config.toml`, `tests/` — do not exist yet.

## Implementation Notes

- `dashboard.py` splits a pure data layer (`fetch_features`, `load_rows`, `build_dictionary`, `label_for`, `to_float`, `format_value`, `domain_for`, `color_scale`, `tooltip_template`, `join_index`, `join_precincts`, `layer_keys`, `detail_panel_fields`, `bbox`, `decorate`, `detail_records`, `build_deck`, `selected_props`) from the Streamlit UI. `streamlit` is imported at the top as a normal dependency and `main()` runs only under `__main__`, so `import dashboard` works with no run context. (The earlier lazy `try: import streamlit / st = None` dance is gone: it typed `st` as `Optional[Module]` and produced ~18 "not a known attribute of None" errors for a condition that never occurs — streamlit is a declared dependency.)
- `decorate()` returns a **list of pydeck records**, not a FeatureCollection: polygon rings under `__rings`, the layer's own properties promoted to top-level keys, plus `__color`, `__matched` and the five pre-formatted `v_<field>` values. `build_deck` feeds that straight to `data=` and the accessors name record keys. See the corrected API facts in Code Map — the browser parses these strings, it does not run them.
- `detail_panel_fields()` decides Decision 1c from the data (drop fields blank in *every* row) rather than hard-coding the 17, so a field that later gains values appears without an edit. `NO_DATA_FIELDS` is asserted against it, keeping the frozen row checkable.
- `build_data_dictionary.py` gained `READABLE_OVERRIDES` (54 entries), applied *after* label selection so it corrects DFS-inherited and `MANUAL` labels alike, plus a guard raising on an override naming a field no longer in the CSV (Decision 2b). `data/raw/` stays read-only.
- **No borders at all since 2026-11-12 (later request).** `stroked=False` is required explicitly because `PolygonLayer.defaultProps` sets `stroked:true`; booleans serialise as plain values, unlike the string props of fc08df5. `LINE_COLOR`, `get_line_color`, `get_line_width` and `line_width_min_pixels` are all gone, and a test asserts no `line`-prefixed prop survives. Picking is unaffected: the fill sublayer — whose shader writes the picking colour — is gated on `filled`, never on `stroked`. `auto_highlight` is kept as the one remaining hover affordance, but note it blends against a zero-alpha fill, so it may be faint on an empty precinct; unverified, since headless deck.gl never registers synthetic pointer input.
- **`FILL_ALPHA` (200) is the single opacity knob** for data-bearing precincts, since 2026-11-12. `color_scale` interpolates `COLOR_LOW`/`COLOR_HIGH` as plain RGB and *appends* `FILL_ALPHA` afterwards, so the two ramp endpoints can never disagree about alpha. That matters concretely: `zip()` truncates to the shorter list, and the palette committed in c6c2cbf had `COLOR_LOW = [251,210,212]` (3) against `COLOR_HIGH = [236,31,39,255]` (4), which silently stripped the alpha channel from **every** colour the ramp produced and left `tests/test_dashboard.py` red at `len(colored) == len(empty) == 4`. The module now asserts both endpoints are 3-wide, and a test asserts the alpha of the scale at t=0/0.5/1 is exactly `FILL_ALPHA`. No-data precincts are exempt: they return `NO_DATA_COLOR = [0,0,0,0]` before the knob is consulted.
- **The title is the selected metric** — `st.title(labels[field])`, chosen before the layer is fetched so it still names the field on the offline path. It used to be the fixed string "Precinct choropleth"; a test pins it to the sidebar's own value, because a title drifting from the metric would misreport the map, which is worse than a generic heading.
- **`legend_html(domain)`** renders under the map through `st.html`: a 300×14 CSS gradient labelled with that field's populated min/max, plus a key for the empty style. Its swatch colours come from `color_scale`, so they cannot drift from the map and they follow `FILL_ALPHA` automatically. Both degenerate domains are handled — `None` (no precinct carries the metric) and `lo == hi`, where a gradient would claim a spread the field does not have. The empty-style swatch needs its own dashed outline because that style is a transparent fill with no border: without it the key draws nothing, and on the default metric it describes 767 of 791 precincts.
- `field_domain()` is now the single source of the colour range: `decorate` and the legend both call it, so the map and its key cannot end up describing different numbers.
- **Colour and tooltip are two lists now, and the coupling lives in `decorate()`.** `tooltip_template()` emits `{v_<field>}` for every `TOOLTIP_FIELDS` entry, so `decorate()` must write exactly those record keys — it iterates `TOOLTIP_FIELDS`, *not* `CHOROPLETH_FIELDS`. Getting that wrong is invisible to every Python-side check: the token is well-formed, the template still parses, and Streamlit simply renders an unresolved token as its own literal text, which is what put `v_2024_prop_r_for` on the screen. A test now resolves every template token against the actual records handed to the layer, which is the assertion that was missing.
- **Correction to a note that sat here for days:** this line claimed the environment had no browser. It has one — chromium plus puppeteer-core, used repeatedly against this app. That sentence is what let the tooltip bug ship, so the `## Verification` manual checks below are now executed here rather than handed over.

### Post-delivery defect, found by the human running the app (2026-11-12)

Browser crash on load — `Error: Unexpected "=" at character 2` in `DeckGlJsonChart…js`. Not in the 16 findings above: the quick lens reviewed by inspection and could not execute the renderer, and every Python-side check in the suite passed against it.

- **Root cause.** The plan's Code Map asserted "`@@=` marks a JS string" and "a FeatureCollection dict is accepted as `data`". Both wrong. pydeck prefixes *every* string layer prop with `@@=` (`bindings/layer.py:99-101`); `@deck.gl/json` then **parses** it with a restricted expression grammar (literals, record-key lookups, `+`, ternary) and does not evaluate JavaScript. So `getFillColor="d => d.properties.__color"` throws at the `=` — index 2, matching the error exactly — and the `{token}` tooltip was a second crash queued behind it (`Unexpected "{" at character 12`). Reproduced with the real converter, not inferred.
- **Why review missed it.** `## Tasks` asked for a test that `Layer(id=…)` equals the selection key; the implementation asserted `emitted["getFillColor"] == "@@=d => d.properties.__color"` — i.e. the test *pinned the broken string*, turning the defect into a green check. A test written from the plan's false API fact cannot detect that fact.
- **Fix.** `decorate()` now returns a list of pydeck records (rings under `__rings`, layer props and the five formatted values promoted to record keys); accessors name those keys; `tooltip_html` → `tooltip_expression`, which concatenates Python-interpolated labels with record lookups. `tests` gained `grammar_ok()`, which rejects `=>`, `{}`, and calls in any `@@=` prop and checks each named key exists on the records — the guard that was missing.
- **Verified in the renderer**, which is what had never happened: chromium + WebGL2, **0 console/page errors**, polygons actually drawn (9 distinct colours sampled across a non-empty canvas), correct captions, no raw field name in the UI. `mypy --disallow-any-generics` clean, which also closes the 48 pasted linter errors.
- **Side effects worth noting.** Dropping `copy.deepcopy` (records are built fresh) took `decorate` from 221 ms to **2 ms** per rerun, so quick-lens finding 13 — rejected then as "low, deepcopy is load-bearing" — is now moot: the copy is gone and nothing depended on it. `bbox` rewritten to collect points first, which also fixed a genuine `tuple[float | None, …]` type error.
- **Retracted 2026-11-12 — this line was wrong, and it cost a bug.** I wrote that headless Chromium could not register hover or click. It can: `page.mouse.move`/`click` against the canvas drive deck.gl picking normally. ### Second post-delivery defect, found by the human (2026-11-12): no tooltip on hover

Reported as "when I hover my mouse over a precinct I don't see any tooltip pop up". Confirmed and fixed.

- **Root cause.** The tooltip was set on the `pdk.Layer`. `st.pydeck_chart` has no `tooltip` parameter: it reads the tooltip only from `Deck(tooltip=<dict>)`, ships it in a dedicated protobuf field, and passes deck.gl its own `getTooltip`, overriding the layer prop. So our string rode along inside the serialised spec, unread, while the chart rendered perfectly. Diagnosis was one call: `_get_pydeck_tooltip(build_deck(...))` returned `None`.
- **Why the suite could not see it.** Every tooltip assertion tested the *string* — that it carried five labels and five slots, that it survived `.to_json()`. All true, all irrelevant to whether anything displays it. The change from HTML to a `@@=` expression (fixing the crash above) moved the string between grammars without ever questioning the transport, and my `grammar_ok()` guard actively blessed the wrong form for this channel.
- **Fix.** `tooltip_template()` emits a `{token}` template shipped as `tooltip={"text": ...}` on the **Deck**; the inert layer prop is deleted. `text` over `html` keeps it `innerText`, so precinct ids arriving from the live layer cannot inject markup.
- **Guard added.** The suite now asserts `_get_pydeck_tooltip(deck)` returns our dict with the exact template, that `html` is absent, and that no `tooltip` key survives on the layer — i.e. it tests the *transport*, not just the payload.
- **Verified in chromium** (the check that had never been run): hovering produced a visible `.deck-tooltip` reading `Precinct 2152` / `Prop A No Share (Canvassed): —` / `2024 Prop R (For): 78.1%` / … with all five labels, em-dashes for blanks, `display: block`, `visible: true`, 0 console errors. Clicking the same point replaced the "Click a precinct" prompt with the labelled detail table, and a second click on a precinct with no CSV row showed the "has no data in this research extract" message instead — so the frozen matrix rows for hover and click are now demonstrated rather than asserted.

## Design Notes

Filled-vs-empty is the product for sparse fields, so no-data is a first-class style, not an absence of style — drawn as nothing at all rather than as a grey wash — no fill, no border — so the basemap shows straight through the precincts that carry no value (renegotiated by the human 2026-11-12; grey at first delivery, then transparent fill, then borderless). The default metric is populated for 24 of 84 matched precincts (a canvass-coverage proxy, not a result) — the map is intentionally mostly empty at default.

Normalize each color scale on the **selected field's own populated min/max**, never a fixed 0–1: `response_rate` spans 0.00–0.40 while `canvass_attempts` spans 0–613, so a shared domain would flatten one and crush the other. Interpolate two colors across that domain; leave blank unfilled.

Data-bearing precincts paint at `FILL_ALPHA` (200/255 ≈ 78%) so the basemap stays readable underneath them; the knob is one constant, deliberately not baked into the palette. Measured cost of 200 vs 255 in the renderer: fill saturation drops ~22% at *both* ends of the ramp (light pink 0.221→0.174, strong red 0.869→0.675), i.e. the wash is uniform rather than eating only the pale end. Raise toward 235 for a stronger map that still shows tiles; 255 is solid.

Read a field's units from the field, not from each value: `canvass_attempts` is an integer count, so 0 attempts must render `0` and not `0.0%`. Deciding share-vs-count per value made one column tell three stories (`0` → "0.0%", `1` → "100.0%", `113` → "113"). `domain_is_share()` answers it once per field from the populated range, and the tooltip and the legend both ask it, so the two can never disagree.

Cache geometry with `st.cache_data(ttl=...)` so a 4.6 MB fetch does not repeat on rerun — switching the color field must not refetch.

Tooltip values are interpolated as plain text (never HTML — the channel assigns `innerText`), and every value shown is a locally formatted number. Format numbers only — never pass a source string through unformatted.

Decision 1c drops the 9 no-data fields with no visible trace; their absence reads as a scoping choice rather than a data gap, which is the tradeoff accepted here.

Keep the choropleth readable without the basemap: precincts that carry a value stay distinguishable if tiles fail to load, since that path is third-party and offline is a supported state. *(Relaxed 2026-11-12: with borders removed there is nothing at all to show empty precincts' geography, so tile failure now costs the map its structure, not just its wash. Accepted knowingly — it is the direct consequence of asking for no border lines.)*
